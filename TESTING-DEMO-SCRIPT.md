# Testing / Demo / Training Script

A living, scripted walkthrough for testing the app, demonstrating it to staff, or training polling officers — as opposed to [ROLLOUT-CHECKLIST.md](ROLLOUT-CHECKLIST.md), which is the operational checklist for an actual real polling day. Anything generated while running this script (candidates, codes, votes, Election History entries) is test data and must be cleaned up via ROLLOUT-CHECKLIST.md's steps before real polling day.

**How this file is organised**

| Part | What it is | When to use it |
| --- | --- | --- |
| **Part 0** | Prep done *before* staff walk in | Half an hour before the session |
| **Part 1** | The live demo, in running order | With staff in the room |
| **Part 2** | Regression checklist | Re-run before every real polling day |
| **Part 3** | Behaviours that look like bugs but aren't | Read once, so nobody is caught out |

Refer to items by their **title**, not their number — numbers shift whenever the script is edited.

Keep adding to this file as new scenarios come up.

---

## Part 0 — Before staff arrive

The single biggest thing that makes a demo drag is doing setup work in front of an audience. Get all of this done first, so Part 1 opens on a clean, ready system.

1. **Candidates entered for both branches.** Manage Candidates → add at least 3 dummy candidates for every School post (HB, HG, SSC, SRC, SCC) and every House post (HC, HCC, HSC) in every house — **once under the Dwarka sub-tab and once under the AN sub-tab**. Put a photo on a few of them and deliberately leave others without one, so the placeholder can be shown. (Photo will be added next year when we can handle large data associated with it).
2. **Fresh duties for both elections.** Polling Officer Codes tab → **🔄 Start Allotting Duties for a Fresh Election** → **School Elections**, then again → **House Elections**. Every existing code turns white and usable. (Codes left over from an earlier election are red and refused at the booth until this is done.)
3. **Officer codes generated and allotted.** Generate at least: one School code for Dwarka, (for everyone to copy from screen and vote), few school code for Dwarka (to be allotted to staffroom incharge as polling officer), one School code for AN, and one code per house. **Give every code an officer name** (actual incharge) — an un-named code cannot activate a ballot at all. Use "🖨️ Print Code List" to have the slips ready to hand out. Leave the codes **unsent** — sending one is part of the demo.
4. **A paper tally.** Have a sheet of paper ready to act as the **Paper List** for one booth: during the demo, tick it once for every vote cast at that booth.
5. **Nothing left running.** Dashboard should show no active election, poll closed, no banner at the top. If an old recording is still active, close its booths, Verify & Seal them, then use End of Voting.
6. **Devices.** Have the admin dashboard on the projector, a second device (phone or laptop) for the "Ask for Control" demo, one teacher's phone ready for the single-voter demo, and everyone else's phones with the URL already open. The projector computer should have the WhatsApp app installed and logged in (otherwise switch the Send Codes screen to "WhatsApp Web").
7. **Keep one code back.** Hold one named, unused School code aside — you'll need it for the "wrong code type" demo in Part 1 and it must not have been handed out.

> **There is no "Reset Poll" button in this demo — it was removed.** The poll can only ever be opened through "Start the Voting Process". **End of Voting** is the only, and correct, way to finish any election — and it needs every code of the election either deleted, or closed and verified & sealed first. (See Part 3.)

## Part 1 — The live demo

Each step has a one-line **Say:** cue — the point staff should take away — so the narration doesn't have to be improvised.

### Act 1 — Only one person controls the election

1. **Asking for control.** Log in to the super admin on the projector, then log in again from the second device. The second login shows "The admin console is in use on (device)…" with an **Ask for Control** button. Press it: the projector plays a sound and shows an Allow / Deny popup naming the second device. **Deny** — the second device is told "Request refused" and the projector stays in control. Ask again and **Allow** — the second device is in, and the projector is signed out within a few seconds with "You handed control to…". Entering the secret on a second device never evicts the first on its own.
   **Say:** *Only one terminal can control the election at a time. Nobody can take it over without the person in control saying yes — and during an election every request and answer is recorded in the log.*
2. **Log back in on the projector** (ask for control from it, and allow it on the second device), and carry on from there.

### Act 2 — Setting up an election

3. **Show the prep already in place.** Walk through Manage Candidates, and use the **School / House toggle** at the top of the tab to switch between the two sets of candidates, and the **Dwarka / AN** sub-tab to switch branches. Four combinations, one screen.
   **Say:** *Candidates and officer codes are prep work. They're entered once and stay put — they are not wiped when an election ends.*
4. **Duty colours and sending a code.** Polling Officer Codes tab. Point out the summary line and the colours: everything is ⚪ white ("Not sent"). Press **📲 Send Codes on WhatsApp** → **▶ Send Next** — WhatsApp opens with that teacher's message ready, both their codes in one message if they have School and House duty. Send it (or close WhatsApp without sending, and show **Undo**). Back on the Codes tab, that code is now 🟡 yellow.
   **Say:** *White means not sent, yellow means sent but the teacher hasn't used it yet. One click per teacher — and if we're interrupted, it remembers where we stopped.*
5. **Start the Voting Process.** Dashboard → **🗳️ Start the Voting Process**. On the wizard's first step pick **School**. Note the indicator now showing "🏫 School Election chosen" on every step of the wizard. Then click **Abort** to back out without opening the poll.
   **Say:** *nothing can be voted on until the poll is actually opened.*
6. **Un-named codes can't vote.** If you have an un-named code to hand, try it at Activate Ballot — it's refused with "has not yet been allotted to a polling officer", before any other check.
   **Say:** *A code is useless until it's been allotted to a named person. That's the audit trail.*

### Act 3 — Guardrails, demonstrated as they come up

7. **Check-in before voting opens.** On a teacher's phone, enter the code you just sent at Activate Ballot. The teacher sees a green **"✓ Your code is correct and you are marked as ready. Voting has not started yet"**. On the projector, within a few seconds, that code turns 🟢 green with "Ready since …". Tick **"Not ready yet only"** to show the list of who still needs phoning.
   **Say:** *Green means the teacher has their code and is at a kiosk. On the morning, this is how we know every booth is staffed before voting starts.*
8. **Wrong code type, poll closed.** Use a **House** code at Activate Ballot now. Because voting hasn't started, it just checks in (green "marked as ready" message) — the wrong-type check comes later. Leave it for the moment.
9. **Empty post blocks opening.** *(Optional, if you have a spare minute.)* Delete every candidate from one post, reopen **Start the Voting Process**, and try to reach "Open the Poll" — it's blocked with a message naming the empty post. Add a candidate back and continue.
   **Say:** *The app will not let you open a poll that a voter could get stuck in.*
10. **Open the poll.** Reopen **Start the Voting Process**, go through to the final **Open the Poll** step (this starts the election run and opens the poll together). The **"Election for School Posts" banner now appears** at the top of every screen, admin and voter alike.
    **Say:** *The banner is the single signal that voting is genuinely live.*
11. **Now retry the House code** — this time the message is "this code is for House Elections and cannot be used while School Elections are active."
12. **Mistyped code.** Enter any nonsense code — "Incorrect officer code", no crash, no blank screen.

### Act 4 — Voting

13. **First vote, on the projector.** Use a School code for **Dwarka** to activate a ballot and cast a vote. There must be a loud beep, and the station's vote count is shown. Explore what else the voter sees after casting.
14. **Changing your mind.** Cast a 2nd vote, changing the candidate *before* reaching the summary. Cast a 3rd, changing the candidate *from the summary screen* just before submitting.
    **Say:** *A voter can change their mind right up until they submit — and not after.*
15. **Candidate with no photo.** Point out the placeholder on the candidate you deliberately left photo-less.
16. **One teacher, one phone.** Give one teacher their own code and have them vote from their mobile while the **Live Results** tab is on screen. **Tick the paper tally for every vote at this booth** — it's the Paper List for Act 6.
17. **Everyone at once.** Have all teachers present open the app on their phones. Give them all the same **Dwarka School** code, and have them vote together for one candidate agreed unanimously. **Physically count the people voting**, and show the count move by exactly that number.
    **Say:** *One code can serve a whole queue — it doesn't get used up. What gets used up is each individual ballot.*
18. **Now the other branch.** Hand two or three teachers the **AN** School code instead, and have them vote. Then on the Dashboard switch the branch selector from **Dwarka** to **AN** and back.
    **Say:** *The two branches are counted entirely separately. A Dwarka code can only ever produce a Dwarka vote, and it can only ever see Dwarka candidates — the server enforces that, not the phone.*

### Act 5 — Results and reports

19. **Live results.** Live Results tab → show the totals, the branch selector, and the School/House toggle (you can look at House while School is the one actually running, without disturbing anything).
20. **Download the live report, per branch.** Dashboard → **🖨️ Download Dwarka Report** and **🖨️ Download AN Report**. Check the "total votes cast" on each report against the number of people you physically counted in the "Everyone at once" and "Now the other branch" steps.
    **Say:** *These two buttons always show the current position — during the election that's live, and after it closes it's the final result. They never stop working.*
21. **Save a checkpoint.** **📋 Save to Election History** on the Dashboard. This files a permanent record and changes nothing — the poll stays open and no votes are touched. Show the new entry in the Election History tab.
22. **Pause for a break.** Click **⏸ Pause Polling** (it's one button — it swaps to **▶ Re-start Polling** in the same spot). Read out the line under it. Try Activate Ballot on any device — the code is accepted as a check-in, but no ballot opens. Then try Manage Candidates → attempt to edit or delete a candidate — **also refused**, even though the election is only paused, not ended.
    **Say:** *Pausing only stops voting. Everything else about this election — including the fact that candidates are locked — stays exactly as it was. It comes back exactly the same way when you re-start.*
23. **Re-start.** Click **▶ Re-start Polling**. Confirm voting works again immediately.

### Act 6 — Closing booths and finishing the School election

24. **Try to switch type first.** Open Start the Voting Process and try to pick House. It's refused — "a recording is currently active, close it before switching election type."
    **Say:** *You can't accidentally start the next election on top of one that's still running.*
25. **End of Voting is refused while booths are unchecked.** Dashboard → **End of Voting** → confirm. It's refused, listing every booth still polling, every closed booth not yet sealed, and any unallotted code. Show the **"Before End of Voting"** box just above the button: it says the same thing before you even click.
    **Say:** *No election can be declared closed until every booth's count has been checked against its Paper List.*
26. **Close a booth — both ways.** Have the teacher from the "One teacher, one phone" step use "Close Polling at This Booth" on their code; their code turns 🔴 red ("Polling closed"). Try to activate with it again — refused. Then show the admin's own **Close** button on another code doing the same thing directly, for when a teacher can't reach a kiosk; **Reopen** it to show that's possible too (until a booth is sealed).
    **Say:** *That's how an officer signs off, or how you can do it for them — and red means it's waiting for us to check it.*
27. **Verify & Seal — a mismatch first.** On the red booth press **🔒 Verify & Seal**. The window shows the app's count. Type a number one *less* than your paper tally — "The counts don't match", sealing stays locked, and an **Order Re-poll** button is offered. Don't press it.
28. **Verify & Seal — matching.** Type the real number from your paper tally — "✓ The counts match" — and press **Verify & Seal**. The booth turns ⚪ white with 🔒 Sealed and "Paper List N · App N"; its Close, Reopen, Re-poll and Delete buttons are gone.
    **Say:** *Sealed is final. The booth can't be reopened or re-polled, and not one more vote can be added to it.*
29. **Close and seal every other School booth**, the same way — including any booth with no votes (seal it with a Paper List of 0) — and **Delete** any unallotted (unnamed) School code. Watch the Dashboard's "Before End of Voting" box count down to "✓ Every booth is closed and sealed".
    **Say:** *One rule: every code is either deleted, or closed and sealed. Until then, nobody can end the election by mistake.*
30. **End of Voting.** Dashboard → **End of Voting**. This time it goes through: it saves the final result to Election History and closes the poll. The banner disappears.
31. **Confirm nothing was lost — and nothing went blank either.** Polling Officer Codes tab — every code and every officer name is still there; all codes of this election are now 🔴 red or 🔒 sealed (duty over — they become usable again only with **Start Allotting Duties for a Fresh Election**, or when the next School election is started). Live Results tab — still shows the final numbers, exactly as they were the moment voting ended (the live count does **not** reset here; only Start the Voting Process resets it, when the next School election actually begins). Election History — the School election's final record is there, and did **not** get duplicated by the checkpoint you saved earlier.
32. **Reports still work.** Hit **Download Dwarka Report** again now that nothing is running — it shows the School election's final result.

### Act 7 — The House election (shorter; show only what differs)

33. **Start House.** Start the Voting Process → House → through to Open the Poll.
34. **School code is now refused.** Try the School code — refused (its duty for the School election is over).
35. **A house code opens only its own house.** Activate with, say, the Prem code and show that only Prem's candidates appear. The house comes from the code itself; the officer never picks it.
    **Say:** *Nobody has to remember which house they're running. The code knows.*
36. **Vote, and show Live Results grouped by house.**
37. **Order a re-poll.** Cast a few votes through one house code and note the live results. In the Codes tab press **Re-poll** on that code, choose "Vote count mismatch", add a note, choose the same teacher, and type CONFIRM. **Show:** the live results drop by exactly that booth's votes; the code row reads "RE-POLLED → (new code)" with "N cancelled"; trying to activate with the old code is refused with a re-poll message; the new code is ⚪ white, marked "Re-poll of (old code)", and appears in **📲 Send Codes**. Activate with the new code — it turns 🟢 green, votes normally, and its votes count.
    **Say:** *The cancelled votes aren't deleted — they're kept as evidence — they just never count. The old code can never be switched back on, and the re-poll gets a brand-new code.*
38. **Delete a no-show's code.** Give a code to a teacher on the roster, name it, then delete it without it ever being used — confirm this succeeds, since a code is only permanent once it's actually cast a vote (or been sealed or re-polled).
    **Say:** *A whole staff list gets a code each. Some won't show up — deleting theirs is routine, not a red flag.*
39. **Close and seal every House booth** — including ones with no votes (Paper List 0) and the re-poll's new code — delete any unallotted House code, watch the Dashboard's "Before End of Voting" box reach "✓ Every booth is closed and sealed", then **End of Voting** for House.

### Act 8 — After everything is closed

40. **Reports survive.** With nothing running at all, **Download Dwarka Report** / **Download AN Report** still work and show the House election's final result — the most recently closed election. They never go permanently dark.
41. **Election History.** Show **View/Print Dwarka** and **View/Print AN** on a past entry. Point out that the vote totals on these match what was counted on the day. In the turnout table, point out "🔒 Verified against the Paper List" on each sealed booth, and the re-polled booth's "Re-polled: N votes cancelled, reason, new code". Show renaming an entry.
42. **Officer turnout.** On an Election History report, untick **"Include polling officer turnout"** for a results-only copy to hand out; it's ticked by default.
43. **Activity Log, by election name.** Open the **Activity Log** tab. Both elections you just ran show up as named, clickable entries under "Elections" — click **House 3 try** (or whatever you named it) and the log narrows immediately to just that election's actions, no dropdown or Search press needed. Point out the seal entries (with both counts), the re-poll entry, and — if you did Act 1 during an election — the requests for control. Click **All Elections** to go back to everything.
    **Say:** *This log runs for the whole span of an election — start to end, including through any pause — and it's permanent. Nobody, including me, can edit or delete an entry in it.*
44. **Storage indicator.** Point at the green "Storage: OK" on the Dashboard once, so whoever is on duty would recognise the red warning banner if storage ever failed for real.
    **Say:** *If this is ever red on polling day, stop and call me.*

## Part 2 — Regression checklist

Re-run before every real polling day. Everything below is verified working as described unless noted.

### Admin session & access
- **Backgrounded tab stays logged in.** Leave the admin tab minimised for several minutes, come back, confirm you're still logged in (fixed 2026-09-23 — a quiet tab used to get silently logged out).
- **Logout frees the slot immediately.** Log out, log straight back in from the same device — no "session already active" conflict. *(Verified 2026-09-24.)*
- **Wrong secret.** A few wrong attempts in a row each give a clear "incorrect secret" message. *(Verified 2026-09-24.)*
- **Handing over control needs the consent of the device in control** (changed 2026-10-01; the old one-click "Take Over This Terminal" is gone). A second device is refused and can only **Ask for Control**. On the device in control: a popup with a sound and a flashing tab title. **Allow** → control moves, the old device is signed out within ~5 seconds. **Deny** → asker sees "Request refused". **No answer for 1 minute** → asker sees "No answer…". **Cancel Request** on the asking device → the popup disappears on the other. **Close the controlling tab and wait 3+ minutes** → the second device can log in without asking. *(Covered by automated tests; **still needs a real two-device check**, including with the controlling tab in the background.)*

### Candidate management guardrails
- **School posts lay out full-width, one post per row, same as House.** School candidate cards used to sit in a narrow multi-column grid (5 posts side by side); editing a name there could push the Save/Cancel buttons off the edge of the card, out of reach. Fixed 2026-09-25 by giving School the same full-width, one-post-per-row layout House already had, where this never happened. **This is a pure CSS/layout change and cannot be meaningfully checked by an automated test (no real browser layout in the test environment) — needs a real browser check:** open Manage Candidates → School, click Edit on any candidate, confirm the ✓ Save and ✕ Cancel buttons are both fully visible and clickable, at both a normal desktop width and a narrow/mobile width.
- **No edits for as long as an election is in progress — including during a Pause Polling break.** Add / edit / delete from Manage Candidates are all blocked with the same explanation, whether polling is open or paused. *(Fixed 2026-09-24: previously this checked only "is polling open right now," so pausing — a routine lunch-break action — silently unlocked candidate edits mid-election, even though the wizard's own "Candidates will be locked" step implied otherwise. Verified against a live server: blocked while open, blocked while paused, blocked again once re-started, allowed only after End of Voting.)*
- **Empty post blocks Open Poll.** Blocked with a message naming the post; add a candidate back and it opens. *(Verified 2026-09-24.)*
- **Missing photo.** The voting screen shows a sensible placeholder, not a broken image.

### Officer codes
- **Mistyped code** → "incorrect officer code", no crash. *(Verified 2026-09-24.)*
- **Un-named code** cannot activate a ballot, and this check fires *before* the poll-closed and wrong-type checks. *(Verified 2026-09-24.)*
- **Closed booth** refuses activation; admin Reopen makes it usable again. *(Verified 2026-09-24.)*
- **Admin can close a booth directly** from the Officer Codes tab (a new "Close" button next to Delete, shown on any open code) — no need to open a kiosk tab and enter the code there to do the officer's own "Close Polling at This Booth" on their behalf. *(Added 2026-09-25. Verified end to end: closes the code, a subsequent Activate Ballot with it is refused, Reopen makes it usable again.)*
- **Deleted code** → "incorrect officer code". *(Verified 2026-09-24.)* **A named-but-unused code can now be deleted** (revised 2026-09-25, by direct request — see the Part 3 entry below for why); the only remaining condition is a vote actually cast under it, which still blocks deletion regardless of naming. *(Verified end to end: a named, unvoted code deletes cleanly (204); a named code with one vote cast under it is still refused (409).)*
- **Codes survive an election.** End an election with a code allotted and its booth closed, start a new election of the same type — the code, officer name and allotment are all still there and the booth is usable again. *(Verified 2026-09-24.)* The code's *vote count* stays exactly as it was at End of Voting (it does **not** go to zero at close) -- it only resets the moment a new election of that type is actually started. Verified end to end: 3 votes cast, End of Voting, voteCount still 3; started a fresh election of the same type, voteCount then 0. *(Since 2026-10-01: between End of Voting and the next Start, every code of that election is red and refused — see "Duty colours" below.)*

### WhatsApp sending, duty colours, Verify & Seal, re-poll (added 2026-10-01)
All of these are covered by automated tests; **none has yet been checked in a real browser** — run each once before relying on it.
- **Send Codes on WhatsApp.** Bulk Allot a small teacher list, close the upload window, open **📲 Send Codes** — every teacher is listed (numbers were saved). **Send Next** opens the WhatsApp *app* (not a new browser tab) with the message ready; a teacher with School and House duty gets one message with both codes. The row turns ✓ Sent; refresh the page — the tick is still there. **Undo** clears it. Switch to "WhatsApp Web" — every message reuses one browser tab. A teacher with no valid number appears at the bottom; typing a 10-digit number and Save moves them into the list.
- **Fresh duties.** **🔄 Start Allotting Duties for a Fresh Election** → School: every School code (both branches) turns white; House codes are untouched. Refused while a School election is running.
- **Duty colours.** White (not sent) → yellow (sent) → green (entered on a kiosk, "Ready since…", even with the poll closed — the teacher sees the green "marked as ready" message) → red (booth closed, or End of Voting) → white 🔒 (sealed). The summary line counts match; "Not ready yet only" shows just white and yellow. The tab updates by itself within ~5 seconds with the poll closed.
- **Check-ins don't lock a phone out.** Enter a correct code 35+ times on one phone before voting opens — still the green "marked as ready" message, never "Too many incorrect codes".
- **Verify & Seal.** On an open booth there's no Verify & Seal button; close it and the button appears. A wrong Paper List number keeps sealing locked and offers Order Re-poll; the right number seals it (white, 🔒 Sealed, "Paper List N · App N", no Close/Reopen/Re-poll/Delete). Start a ballot on that booth *before* sealing, seal, then submit — the vote is refused with a "sealed" message and the sealed count is unchanged.
- **End of Voting needs every code deleted or sealed (one rule, 2026-10-01).** With a booth still polling, a closed booth unsealed, or an unallotted code left, End of Voting is refused and names each; the Dashboard's "Before End of Voting" box shows the same counts and updates within ~5 seconds. A booth with no votes is sealed with Paper List 0; an unallotted code can't be sealed (delete it). *(Verified 2026-10-01 in a real browser on a local copy: the server refused with all three kinds listed; sealing a 0-vote booth through the screens was accepted (Paper List 0 · App 0), saved, logged, and dropped from the Dashboard box.)*
- **Re-poll.** Live results and the Dashboard total drop by exactly that booth's votes; the old code reads "RE-POLLED → new code" with "N cancelled", is refused at the kiosk with a re-poll message, and has no Reopen/Delete. The new code keeps the same branch and house, starts white, appears in Send Codes, votes normally, and is marked "Re-poll of …". A ballot opened on the old code just before the re-poll is refused on Submit. Re-poll is not offered on a sealed booth or once the election has ended. The Election History report shows the cancelled count, reason and new code.

### Voting session edge cases
- **5-minute timeout.** Activate a ballot and leave it untouched for over 5 minutes — the session is reported as expired (changed from 10 to 5 minutes on 2026-09-24). **Still needs a real timed run-through in a browser.**
- **Refresh mid-ballot (F5).** The voter lands back on Welcome with no error, and the officer can activate a fresh ballot with the same code. The in-progress ballot lives only in the tab's memory — never a cookie or local storage — so a refresh can never leave a stuck screen.
- **Refresh after "Vote Recorded".** Also just returns to Welcome, with no way to resubmit. The vote is recorded and the activation invalidated server-side the moment Submit succeeds, before the confirmation even renders. *(Verified 2026-09-24: a second submit on the same token is refused with "This ballot has already been submitted.")*
- **Back button** cannot un-confirm a vote or reopen the ballot — the confirmation is in-app state, not browser history. Refresh is the meaningful test, not Back.

### Poll lifecycle
- **"Pause Polling" and "Re-start Polling" are now one button** that swaps its own label (2026-09-24) — red "⏸ Pause Polling" while voting is live, green "▶ Re-start Polling" while paused, in the same spot, rather than two separate buttons where one was always greyed out. **And the whole "Voting" section only appears once an election has actually been started** (fixed the same day, after the first version still showed a permanently-dimmed "Re-start Polling" and both explanatory paragraphs while "No voting is in progress" was showing right above it) — before Start the Voting Process, this section isn't in the page at all.
- **What Pause actually means, stated plainly on the Dashboard itself** (below the button, 2026-09-24): "Pause only stops the voting process. Any feature available after the 'End of Voting' remains inaccessible." Everything that stays locked for the whole election (Manage Candidates, switching election type) stays locked through a pause exactly as it does while polling is open. Only End of Voting changes that. See the Candidate management guardrails entry above for the bug this closes.
- **Pausing no longer prompts "Save this election to Election History?"** (removed 2026-09-24) — that prompt predated Start the Voting Process/End of Voting and treated a pause like an ending point, which it isn't. A mid-election checkpoint is still available any time via "📋 Save to Election History"; a real ending archives automatically via "End of Voting."
- **No duplicate history entry.** "Save to Election History" followed by End of Voting produces one record, not two. *(Verified 2026-09-24.)*
- **There is no "Reset Poll" / "Clear Test Votes" button anywhere in the admin dashboard any more (removed 2026-09-24).** It existed to guard against votes existing with no election recorded against them -- but the poll can only ever be opened through Start the Voting Process's own final step (which starts the election in that same click) or "Re-start Polling" (which only works while a run is already active). Neither can ever produce that state, so it's unreachable through the app, and the button had nothing left to protect against. `POST /api/poll/reset` still exists on the server as a maintenance-only escape hatch, not reachable from any button, for the one remaining case: someone calling the API directly rather than through the app.
- **Close the poll mid-voting.** No new ballot can be activated afterwards, and votes already fully cast are unaffected. **Note:** an already-activated but not-yet-submitted ballot *is* invalidated the instant the poll closes — that voter cannot submit ("Invalid kiosk session token"). Plan for that if a real voter is mid-ballot when Close Poll is clicked. *(Verified 2026-09-24.)*
- **Switching election type is blocked while a recording is active.** *(Verified 2026-09-24.)*

### Branch separation (Dwarka / AN)
- **A booth can only vote for its own branch.** An AN-coded ballot submitting a Dwarka candidate's id is rejected outright by the server, even though that candidate genuinely exists for the post. The candidate list the voter sees is a display convenience; the kiosk session's branch is the trust boundary. *(Verified 2026-09-24.)*
- **A house booth can only vote for its own house.** Same mechanism. *(Verified 2026-09-24.)*
- **Per-branch report totals.** A branch report's "total votes cast" matches the number of people who actually voted in that branch, and the two branches add up to the combined figure. *(Fixed 2026-09-24 — see the change log below.)*
- **Run the whole of Part 1 once per branch** once AN's real candidate list is entered, plus one pass specifically checking that a Dwarka code never surfaces AN candidates or votes, and vice versa.

### Reports & history
- **Download Dwarka/AN Report** work during an election (live figures) *and* after it closes (that election's final result). They do not go permanently disabled. *(Verified 2026-09-24.)*
- **Print Officer Turnout** for both School and House — totals match Live Results, layout is print-ready. **Still needs a real browser check for print layout.**

## Part 3 — Behaviours that look like bugs but aren't

Worth knowing before someone reports them as faults.

- **What "Pause Polling" means, precisely:** pausing removes only the ability to vote, temporarily. The election itself stays fully in progress for the whole time it's paused — the same as while polling is open — right up until End of Voting. Nothing that's locked for the duration of an election (candidates, the election type) becomes available just because polling happens to be paused.
- **There is no "Reset Poll" button any more.** It used to sit, prominent and orange, next to the report buttons in "Records & Reports" -- but the poll can only ever be opened through Start the Voting Process (which starts the election in the same click), so there was never a way to reach the state it was meant to fix. Use **End of Voting** to finish an election properly; it saves the final result and closes the poll -- it deliberately leaves the votes themselves untouched, see the "Live Results does NOT go blank" entry above.
- **Live Results does NOT go blank when an election ends -- it keeps showing the final numbers.** End of Voting saves the result to Election History and closes the poll, but deliberately does not touch the live vote count (2026-09-24, reversed from an earlier version of this app that did reset it here): a school's House/School election runs once a year, so there's no reason for the number everyone just watched fill in to vanish the moment it's over. Live Results, the Dashboard's own total, and each officer code's turnout all keep showing that election's final figures for as long as nobody has started a new election of that type. The live count only resets the moment **Start the Voting Process** is used for that type again -- that action, and only that action, wipes it back to zero. *(Verified 2026-09-24 against a live server: 3 votes cast, End of Voting, Live Results and officer code turnout both still showed 3; started a fresh election of the same type, both then showed 0. The earlier election's archived record in Election History was untouched throughout.)*
- **An officer code's vote count goes to zero when the next election of that type is started** (not when an election ends — see the entry above). Expected: the votes were archived and cleared. That election's turnout is preserved in its Election History entry.
- **A teacher entering a correct code sees "Voting has not started yet" instead of a ballot.** Expected before the poll opens (or during a pause): it's a check-in. The message is green and says they're marked as ready, and their code turns green on the admin tab.
- **Every code is red after End of Voting, and refused at the booth** ("polling duty for it is over"). Expected: the election's duty is over. Press **🔄 Start Allotting Duties for a Fresh Election** (or start that election type again) to make them usable. All codes that existed before the 2026-10-01 update started out red for the same reason.
- **End of Voting refused, listing booths.** Expected: every code of the election must be deleted, or closed and **🔒 Verified & Sealed** — even a booth with no votes. It's the safety valve against ending the election by mistake while booths are still polling (a closed election can't be reopened).
- **A sealed booth has no buttons except the officer-name box.** Expected: sealing is final.
- **A re-polled booth shows 0 "Votes Cast" with "N cancelled".** Expected: the votes are set aside, not deleted. They stay until the next election of that type is started; after that, only the saved report keeps their count and reason.
- **The Allow / Deny popup appeared late, or the request had already expired.** Expected if the admin tab was in the background: browsers slow down background tabs. Keep the admin tab in front during an election.
- **Send Next did nothing.** The WhatsApp app isn't installed on that computer (or the browser's "Open WhatsApp?" prompt was dismissed). Switch the Send Codes screen to "WhatsApp Web".
- **The banner disappears the moment an election ends.** Expected: there is no election open to vote in, so there is nothing to announce.
- **No banner while the wizard is open.** Expected: picking a type doesn't mean voting is possible. The wizard shows "🏫 School Election chosen" / "🏠 House Election chosen" on every step so the choice is still visible.
- **A named code with zero votes CAN now be deleted** (revised 2026-09-25, ELECTION-INTEGRITY-AND-TRUST.md item 3 addendum) — only a code that has actually cast a vote is permanent. This matches how codes are actually allotted now: a whole staff roster gets a code each, sent by WhatsApp, and it's routine for some teachers not to report for duty. Every naming and every deletion is still permanently logged either way, so that history is never actually lost.
- **`?house=` on the results API doesn't narrow the total-votes figure**, only the per-candidate tallies. The admin UI never sends it, so this is not reachable from the app; noted only so nobody builds on it.
